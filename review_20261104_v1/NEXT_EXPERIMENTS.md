# Further-work priorities — design only, not executed

The current evidence is sufficient for a bounded exploratory application result. Additional docking is **not required** to report the oracle-versus-selection distinction honestly. It **is required** before claiming that observed minor-state identity is useful beyond ordinary conformational diversity, or that a trained packer improves docking. None of the designs below has been executed or registered as a new primary study.

## Priority 1: matched rotamer-prior ensemble control

**Question:** at the same diversity opportunity and search budget, do the locations of the observed qFit alternatives contribute more than plausible alternatives from a backbone-conditioned rotamer prior? This directly matches the parent paper's heterogeneity-blind/prior and state-identification controls.

**Fixed conditions:** existing main cohort and component graph; same apo major backbone, residue/chain mappings, pocket definition, ligand conformer/protonation/box, receptor preparation, clash rule and scorer versions. Existing results remain frozen. Keep the one-receptor controls in the main population, while reporting the 107 actual-multiple cases as a prespecified secondary subset.

**Arms:** current single-major receptor, observed qFit ensemble and backbone-conditioned rotamer-prior ensemble. All include the identical all-major receptor in the same slot. For each case, match the actual retained receptor count, at most eight. Vary the same pocket residues. A location-control version should preserve the observed per-residue alternative counts and occupancy weights while drawing replacement wells/geometries from a backbone-conditioned prior; the deliberately changed factor is alternative-state location. A conventional prior-weighted ensemble answers a broader practical question and should be labelled separately, since its state weights also change. Do not describe either as a perfect isolation of every aspect of diversity.

**Feasibility before outcomes:** matching receptor count alone does not match geometric spread or clash attrition. Record per-residue well counts, distance from major, prior probabilities, duplicates and rejected combinations. Define deterministic sampling attempts and feasibility handling before docking. Where an equal-size ensemble cannot be built, record the failure and report prespecified complete-matched feasibility analyses without silently changing the original main cohort. Do not repair prior inputs using ligand RMSD or choose a prior library/temperature on these docking outcomes. Selecting replacements to favour/exclude particular observed wells changes the question and must be declared explicitly.

**Budget:** 50 calls per arm with identical seed list and round-robin slot assignment, exhaustiveness 32 and modes 9. Multiple receptors share the budget. Existing single/qFit runs can be reused only after input and binary hashes are verified; a new prior arm then requires 128×50 = **6,400 apo calls**. At the historical all-case Vina mean of about 22.4 s/call, this is about **40 hours of accumulated call wall time**, or roughly **320 allocated CPU-hours at 8 CPUs/call**; ideal 40–60-way throughput is about 40–60 minutes plus preparation/queueing/I/O. Ligand/receptor mix can change that estimate. Adding a holo prior arm doubles calls. Distinguish this estimate from the earlier reports' “CPU-h,” which summed elapsed call seconds rather than CPU utilisation. No time benchmark for new prior construction exists yet.

**Inference:** positive `prior RMSD − qFit RMSD` favours observed alternatives. Freeze one primary question before execution. If state-specific **coverage** is the intended claim, use oracle RMSD as that primary endpoint and retain selected top-1 and distinct top-5 as secondary utility endpoints. If the intended claim is practical docking improvement, selected top-1 must remain primary and oracle is diagnostic. Do not switch those claims after observing results. Use paired case differences, equal component weighting and component bootstrap, with an explicit family/multiplicity rule if both questions are co-primary. The currently reused cohort is exploratory; stronger confirmation needs additional untouched components.

**Reading outcomes:** qFit > prior in oracle alone supports state-specific candidate coverage in this construction, not useful final selection. qFit > prior in selected top-1 supports a more practical role, within this scorer/preparation/exposure scope. An interval crossing zero is unresolved, not evidence that minor identity is irrelevant. Prior ≈ qFit with narrow bounds would favour general diversity as an explanation only at the declared resolution/margin.

## Priority 2: ensemble/search-seed robustness

The nine gained cases have repeated successful calls, and all-major matched-seed outputs agree exactly. Nevertheless each case used one retained state ensemble and one fixed seed schedule. For a robust mean effect, repeat whole ensembles and disjoint seed blocks with shared schedules across qFit/prior arms; analyse both component and fixed seed/ensemble uncertainty. The ten selected switch cases are appropriate for mechanism development, not an unbiased primary test. Whole-cohort replication has the clearest evidential value but costs roughly another full call budget per new arm/replicate. No new work was run.

## Priority 3: explicit CNN-guided mode, only for a declared sampling question

The previous C run did not test `--cnn_scoring refinement` or `all`. If mismatch is still a scientific target, verify exact mode and complete argv/stdout, run a separately budgeted study and record whether CNN enters final refinement or every search step. Official v1.1 documentation describes substantial mode-dependent slowdowns, so a new empirical cost benchmark is required before choosing scale. This does not answer the observed-state specificity question as directly as the prior control and should not automatically trigger rerunning C. Do not label a non-significant C result as a reason to search modes until a positive result appears.

## Lower priority / existing-data work

Audit GNINA training exposure and biological ligand-role/preparation failures; restore complete argv, output precision, input/binary hashes in future launchers. Whole-cohort distinct-pose first-success rank would strengthen the duplicate analysis but requires all saved geometries and a prespecified clustering convention. None of these substitutes for the matched-diversity control. Direct learned-packer docking would subsequently require the parent model's exposure-controlled cohort, fixed model/state-selection rules and a separate design.

Virtual screening and enrichment are outside scope.
